# Security Audit — Phase 7

Method: every issue below was **verified by executing code** (probe script
against an isolated TestClient + seeded DB, plus targeted unit probes),
not assumed from reading. Non-issues that were checked and cleared are
listed at the end so the audit is honest about what was examined.

Severity: High = exploitable weakness in a security control ·
Medium = weakness with limited impact or needing preconditions ·
Low = hygiene / defense-in-depth.

## Checked and cleared (verified non-issues)

- **SQL injection**: all queries use SQLAlchemy ORM parameterization; no string-built SQL, no `text()` with user input. Malicious `granularity`, `search`, `category`, `quiz_type` inputs rejected or treated literally; tables verified intact (`test_sql_injection_*`).
- **XSS**: no `dangerouslySetInnerHTML` anywhere in `frontend/src` (regression test scans the tree); user content travels as JSON text and React escapes on render (`test_no_dangerously_set_inner_html_in_frontend`, `test_xss_payload_stored_as_text_served_as_json`).
- **URL analyzer network access**: `url_analyzer.py` imports only stdlib parsing (`urllib.parse`, `re`, `ipaddress`); reputation adapter is a pure stub; blocked-socket regression tests at service and API level (`test_no_network_access_during_analysis`, `test_url_analyzer_static_on_sensitive_targets`).
- **File/path traversal**: no file-upload surface, no `StaticFiles`, no user-controlled file paths (route test asserts this); traversal strings are treated as data (`test_path_traversal_inputs_are_data_not_files`, `test_no_file_serving_routes`).
- **Secrets in repo**: grep for keys/passwords/tokens/private keys found only test fixtures (`OTP 482921` redaction fixtures); no `.env` exists; `.env` is git-ignored; `.env.example` holds placeholders only.
- **Passwords in logs**: login flow logs only a 3-char email hint + outcome; probe with a canary password confirmed it never appears in logs.
- **Authorization**: every `/admin/*` endpoint returns 401 without a token; REVIEWER gets 403 on user management + exports; token `role` claims cannot escalate (DB role wins); deactivated users rejected (`test_unauthenticated_admin_access_denied`, `test_reviewer_permissions`, `test_admin_can_do_everything`, `test_token_role_claim_cannot_escalate`, `test_inactive_user_cannot_use_token`).
- **Logout**: client discards the JWT (memory + localStorage) and redirects; invalid tokens are cleared by the route guard. Tokens are stateless with a 60-minute expiry (documented limitation: no server-side revocation list at this scale).
- **ML reliability**: pipeline loads once (module-level cached `_pipeline`, thread-locked); missing model → controlled `ModelUnavailableError` → 503; preprocessing lives in the shared `preprocess` module used by both training and serving; version recorded in metadata and responses; wording stays indicative ("Potentially suspicious"), confidence labeled as model confidence, not fraud probability.

## Residual risks (not fixed — documented limitations)

- In-memory rate limiting is per-process; real enforcement belongs at the reverse proxy (documented in `security.md` + `deployment-checklist.md`).
- No server-side JWT revocation list; mitigation is the short 60-minute expiry.
- Admin JWT lives in `localStorage` (XSS-readable); mitigation is CSP headers + React escaping + short expiry. A httpOnly-cookie session scheme is future work, not adopted (would need CSRF protection + same-site deployment).
- Analytics aggregate in Python over full tables; fine at field-study scale (hundreds–thousands of rows), must move to SQL aggregation past that.
